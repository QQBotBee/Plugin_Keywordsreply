# 关键词回复插件设计

## 目标

在现有 Bee Go 插件模板中实现可持久化的关键词回复功能。用户通过原生 Windows 设置窗口管理多条规则；每条规则配置唯一关键词、匹配方式、大小写策略、触发区域、回复类型和回复内容。消息回调只执行按列表顺序命中的第一条规则。

## 约束与决策

- 支持多条规则，但不允许出现相同的触发关键词。
- 精准匹配比较去除首尾空白后的完整消息；模糊匹配判断关键词是否出现在去除首尾空白后的消息任意位置。
- 大小写敏感度按规则配置，默认敏感。
- 规则严格按设置列表顺序匹配，首条命中后停止。
- 触发区域包括 QQ 好友、群聊、频道消息、频道私信。
- 普通消息和原生 Markdown 支持所有区域；频道私信没有 Markdown API，因此自动降级为普通消息并记录日志。
- 语音、视频和文件仅支持 QQ 好友与群聊。设置窗口禁止媒体规则选择频道区域。
- 所有回调最终返回 `MessageContinue`，不拦截后续插件。

## 数据模型与持久化

新增 `KeywordRule`，字段包括 `Keyword`、`MatchMode`、`CaseSensitive`、`Areas`、`ReplyType` 和 `Contents`。枚举值使用稳定英文字符串：`exact`/`fuzzy`、`friend`/`group`/`channel`/`channel_private`、`text`/`markdown`/`audio`/`video`/`file`。

规则集合由并发安全的 `RuleStore` 管理。设置窗口读取快照，消息回调只读取不可变副本，保存时一次性替换内存规则，避免 UI 线程与消息线程竞争。

配置保存到 `GetAppDataDir()/keyword_replies.json`，格式为 UTF-8 JSON。写盘采用同目录临时文件、关闭文件、重命名替换的原子流程。初始化时创建目录并加载配置；文件不存在视为空配置，格式错误或读取失败则记录日志并保持空规则，不退出 Worker。

## 模块边界

- `keyword_config.go`：枚举、规则模型、校验、规则仓库、JSON 加载与原子保存。
- `keyword_match.go`：区域筛选、首尾空白处理、精准/模糊匹配、大小写折叠和首条命中逻辑。
- `keyword_reply.go`：内容解析、目标绑定、普通/Markdown/媒体发送与错误日志。
- `settings.go`：Win32 窗口生命周期、控件创建、规则编辑和列表排序。
- `plugin_main.go`：初始化配置路径，并将四类消息入口转发到统一处理函数。
- `bee_sdk.go`：为 `MessageTarget` 补充 Markdown、语音、视频和文件发送方法。

当前模板的 `IPCMessage` 只存在于构建阶段复制的 `worker_runtime.go`，导致常规 `go test ./...` 无法编译。实施时先将共享 IPC 消息类型移动到无构建标签的文件，使测试和 Worker 构建使用同一定义。

## 设置窗口

窗口使用标准 Win32 子控件，不继续用纯自绘方式实现表单交互。左侧列表显示规则摘要，右侧提供关键词、匹配模式、大小写敏感、四个触发区域、回复类型和多行回复内容。底部提供“新增”“保存规则”“删除”“上移”“下移”。

保存前执行以下校验：关键词非空、关键词唯一、至少选择一个区域、回复内容非空、枚举值合法，以及媒体规则不得包含频道区域。错误在窗口内明确提示并保持当前编辑内容。保存成功后立即原子写盘并刷新列表；上移/下移后立即保存新顺序。窗口继续保持单实例、居中、置顶和关闭等待行为，并使用可见标签、系统字体及稳定的键盘焦点顺序。

设置窗口的保存按钮使用简洁文案“保存”，不使用“保存规则”。所有可能显示在窗口状态栏中的规则校验和持久化上下文必须使用中文，并采用从 1 开始的规则序号；底层 Windows 错误可以保留原始文本，但前面必须带有清晰的中文操作说明。

## 回复行为

普通消息允许零个或一个 `[图片=XXXX]` 标记，`XXXX` 可为本地路径或网址。存在有效标记时，从文本中移除标记并调用 `SendImage(text, image)`；空地址或多个标记在保存时判定为无效，避免运行时歧义。无标记时调用 `SendText`。

Markdown 内容作为 `MarkdownMessage.Native` 发送，不支持模板 ID、模板参数或键盘配置。频道私信命中 Markdown 规则时使用原内容调用 `SendText`。

语音、视频和文件内容按行拆分，去除每行首尾空白并忽略空行。每个非空项按顺序调用对应媒体 API。任一发送失败时记录包含规则关键词和回复类型的日志，并停止该规则剩余项，避免连续失败造成刷屏。

## 消息数据流

四类消息回调创建本次回调专属 `BeeAPI`，构造区域与目标 ID，读取规则快照并顺序扫描。首条匹配后立即发送对应回复；未命中、配置尚未加载或发送失败均返回 `MessageContinue`。频道消息使用 `subChannelID`，频道私信使用 `channelID`，好友和群聊分别使用 `friendID`、`groupID`。

## 测试与验收

自动测试覆盖：规则重复与字段校验、JSON 往返和加载失败、原子保存、四种区域筛选、精准/模糊匹配、大小写策略、列表顺序优先、媒体行拆分、图片标记解析，以及各回复类型到目标 API 的映射。测试使用可替换发送接口，不依赖真实 Bee。

验证命令为 `go test ./...`、`go vet ./...` 和 `build.bat`。最终还需在真实 Bee 环境手工验证四类回调、配置重启持久化、规则排序、图片路径/网址、Markdown 降级、三种媒体发送、设置窗口单实例及插件禁用/卸载。

## Git 策略

初始模板作为独立基线提交。设计、测试基础设施、配置与匹配、回复发送、设置窗口、回调集成和文档分别形成小型提交；每次提交前运行对应测试，保证任意阶段都可用 `git revert` 回滚。
